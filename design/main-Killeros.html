Codex’s command grammar, intact.

Bare /goal is a read operation. An objective creates and starts work immediately. Control words remain reserved, lower-case-insensitive actions rather than accidental objectives.

/goal

Show status, full objective, active time, turn count, and the commands valid for the current state. If empty, show syntax and one example.

/goal <objective>

Create an active goal and start work. Replacing unfinished work requires confirmation; a completed goal can be replaced directly.

/goal edit

Open the existing objective in Pi’s editor. Preserve its usage counters; editing terminal states reactivates the goal.

/goal pause · /goal resume

Stop or restart automatic continuation without discarding progress. Resume also starts work immediately when the agent is idle.

/goal clear

Remove the goal from the current branch after accounting for the active turn. A second clear reports that no goal exists.

model-only completion

A private goal tool permits only complete or blocked. Final prose alone never ends an active goal.

A small, strict state machine.

Only active schedules another turn. Every other state is quiescent. Transitions are appended before any new model work begins, so reloads and resumes cannot silently resurrect stale state.

none→active→complete /goal objective starts · model completion tool ends
active→paused→active user pause or interrupted run · /goal resume
active→same blocker ×3→blocked hard impasse only · resume starts a fresh blocked audit

Native Pi implementation, no daemon.

The active KillerOS extension owns the state machine. It uses Pi’s command, custom-entry, context-injection, custom-tool, and follow-up APIs—never a child model, polling loop, project file, or background process.

01

Command

Register pi.registerCommand("goal", …); parse control words before treating text as an objective, validate the 4,000-character contract, and use TUI confirmation for replacement.

User boundaryOnly an explicit /goal starts autonomous work.
02

Persist

Append versioned killeros-goal snapshots with pi.appendEntry(). On session start, restore the newest valid snapshot from the active branch—not from unrelated tree branches.

DurabilityResume and reload preserve state; /new begins empty.
03

Inject

For every active turn, add a bounded hidden goal block in before_agent_start: unchanged objective, turn usage, completion audit, blocked audit, and exact stop-tool contract.

Compaction safeThe objective is reconstructed from durable state each turn.
04

Control

Expose one namespaced model tool while a goal exists. It may mark only complete or blocked; user-owned pause, resume, edit, and clear transitions remain inaccessible to the model.

Completion gateNo successful-looking final answer can stop the loop by itself.
05

Continue

After agent_settled, atomically re-read state. If still active and no user message is pending, enqueue one hidden follow-up with triggerTurn: true; never overlap turns.

Single-flight loopOne settlement can schedule at most one continuation.
06

Surface

Add goal state to the existing footer cutdown tiers and render concise transcript summaries for set, view, replace, pause, resume, blocked, complete, and clear outcomes.

Operational clarityState remains visible without becoming a dashboard.
07

Prove

Test parser precedence, branch restoration, replacement confirmation, context injection, tool authorization, settlement races, pause/error behavior, reload, compaction, and narrow footer rendering.

Release gateFake timers and a harness prove no runaway or duplicate turn.

Autonomy must fail closed.

Codex can rely on a dedicated goal runtime and account-limit events. KillerOS must translate that contract onto Pi without pretending unavailable platform signals exist.

InterruptAn aborted turn pauses the goal. It never restarts behind the user’s back.
Runtime failureProvider errors, missing models, failed follow-up delivery, or malformed persisted state pause with an actionable error.
Queued user workUser steering and follow-ups win. Automatic continuation waits until Pi reports no pending messages.
Blocked auditThe same impasse must recur for three consecutive goal turns before the model may mark blocked.
Intentional deltaFirst release omits token budgets and attachment materialization; neither is part of Codex’s user-facing slash syntax. Usage is still measured from Pi session events.

Translate the stack onto Pi.

The first release combines Claude-style role contracts, OpenCode-style safety defaults, and a Codex-style visible lifecycle inside one bounded Pi foreground tool. Persistent teams and autonomous nesting remain intentionally deferred.

01

Package

Ship agents/*.md in the npm package, then discover bundled, personal, and trusted project roles in that order so later sources override earlier names.

Delivery contractFresh installs always have scout, planner, reviewer, and worker.
02

Validate

Require name, description, prompt, access: read | write, and an explicit non-empty tool list. Resolve model as role override then active parent model and thinking; reject unknown tools and unavailable or ambiguous models before spawning.

Configuration contractInvalid roles fail closed with their source file and field.
03

Authorize

For access: read, reject bash, edit, and write. Permit mutation only for access: write, reject concurrent writers in one checkout, and confirm trusted project overrides before use.

OpenCode layerA prompt label never substitutes for an enforced tool boundary.
04

Spawn

Launch pi --mode json -p --no-session --no-extensions --no-skills --no-prompt-templates with the resolved model and explicit --tools; append the prompt from a mode-0600 temporary file.

Pi layerNo child extension discovery, nested subagent tool, or implicit all-tools mode.
05

Control

Give every task an ID and queued, running, complete, failed, cancelled, or limited state. Accept at most eight tasks, run at most four read-only tasks concurrently, and serialize every writer.

Codex layerWait, cancel, and collect by task—not invisible prompt order.
06

Bound

Default to eight turns and five minutes; accept positive role overrides only up to hard ceilings of 12 turns and ten minutes. Retain at most 2 MiB of trace and 64 KiB of stderr per task.

Resource contractOn any limit: terminate, force-kill after five seconds, and report limited.
07

Render

Stream bounded tool activity into one neutral KillerOS container. Collapsed view shows current work and aggregate usage; expanded view shows the retained trace, truncation markers, and final Markdown.

Terminal fitStatus uses words and symbols; coral marks current action only.
08

Return

Return distilled final output capped at 50 KB per task, keep the bounded trace for expansion, and include turns, tokens, cost, model, duration, termination reason, and any truncated-byte counts.

Context boundaryThe parent gets conclusions and honest limits—not every token.
09

Prove

Test all three precedence layers, trust, invalid roles/tools/models, read-only enforcement, extension isolation, task and concurrency caps, writer serialization, turn/time/byte limits, malformed JSONL, failures, usage, and abort cleanup.

Release gateNo orphan process, silent fallback, writer collision, nesting, or unbounded output.

Read wide. Write in sequence.

The inheritance stack is useful only if each source keeps a narrow responsibility: Claude defines roles, OpenCode constrains them, Codex exposes their lifecycle, and Pi executes them.

Default rolesBundled scout, planner, and reviewer declare access: read with read, grep, find, and ls only. Worker alone defaults to access: write.
Parallel writesThe scheduler rejects multiple write-capable tasks in one parallel batch and serializes every writer until isolated worktrees exist.
Child surfaceDisable extension, skill, and prompt-template discovery in children; every task receives an explicit tool list, so omitted tools never mean all tools.
NestingChildren cannot load the subagent extension. The parent remains the only orchestrator in the first release.
LimitsTurns, wall time, retained trace, stderr, batch size, and concurrency all have enforced ceilings; reaching one produces a limited result.
Model resolutionAn omitted model inherits the active parent model and thinking level. Unknown or ambiguous overrides fail before process launch.
CancellationEsc or abort terminates every active child, force-kills after the grace period, and reports partial work as interrupted—not successful.
Inheritance boundaryBorrow behavior and configuration ideas only. Never launch Claude Code, OpenCode, or Codex as a nested runtime.
ScopeThe implemented first release follows this contract; persistent teams, autonomous nesting, steering, and worktree-isolated writers remain out of scope.
